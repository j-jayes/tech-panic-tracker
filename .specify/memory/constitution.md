# Tech-Panic Tracker Constitution

Governing principles for a preregistered, open-data research project collecting and evaluating two centuries of predictions about technology replacing human labour. The full project design lives in `docs/PLAN.md`; registered protocols in `protocol/` supersede both once filed on OSF.

## Core Principles

### I. Human-Verified Records Only
Every record in `data/processed/` is human-verified before it counts. LLM output is a first-draft suggestion that lives in `data/interim/` until a named human coder has checked every field against the source text. Nothing in `data/interim/` is ever analysed, published, or cited.

### II. Full Provenance on Every Row
Every row records who or what created it (coder ID or LLM model **snapshot ID** + prompt version), when, who verified it, and its status (`draft → verified → locked → deprecated`). A record without provenance is invalid by definition and fails CI.

### III. Locked Means Immutable
Once a record is `locked`, it is never edited. Corrections create a new row and set `deprecated` on the old one, preserving the full audit trail. The published dataset is reproducible from the append-only history.

### IV. Registered Protocols Are Frozen
After OSF Registration 1, the search protocol, schema, codebook, and extraction prompts change only via logged, transparent amendments (`docs/decisions/` + OSF). After Registration 2, the evaluation rubric does not change after the first verdict without reporting results under both pre- and post-amendment rules. Controlled vocabularies are append-only after Registration 1.

### V. Evidence-Cited Verdicts
Every ordinal verdict cites at least one outcome-evidence row; `clearly_*` verdicts cite official statistics, census series, or peer-reviewed studies. Verdict rationales reference the operationalised claim — never the author's identity or reputation. Verdicts attach to claims, not persons.

### VI. Generated Counts, Never Hand-Typed
Every count that appears in the PRISMA flow, the codebook, or the paper is generated by script from the logs (`search_log`, `screening_log`, `verification_log`) and canonical CSVs. Hand-maintained numbers are treated as bugs.

### VII. Schema-Validated Data
All CSVs in `data/processed/` validate against `schemas/datapackage.json` (frictionless Table Schema) plus the cross-table pandera rules in `pipeline/validate/` on every commit. Invalid data never merges to `main`.

## Open-Science Constraints

- Data: CC-BY 4.0. Code: MIT. All logs (including the LLM error log) publish with the dataset.
- Copyrighted full texts stay out of the repository — pointers and locators only; verbatim quotes kept short under fair use/fair dealing.
- Releases are semver-tagged (major = schema break, minor = new records, patch = corrections) and archived to Zenodo with a DOI.
- Living authors whose predictions are graded get the §10 PLAN policy: evidence published per verdict, public correction channel, right of reply before v1.0.

## Development Workflow

- Pipeline and analysis work is managed as spec-kit features: `/speckit-specify` → `/speckit-plan` → `/speckit-tasks` → `/speckit-implement`, one directory per feature under `specs/`.
- Two-author review: schema changes, codebook rules, and protocol documents require sign-off from both authors (Jonathan Jayes, Ben Schneider) before merging; a solo commit may not change a registered artifact.
- Analysis scripts in `analysis/` must run end-to-end from `data/processed/` with a single entry point; anything irreproducible is not a result.

## Governance

This constitution supersedes ad-hoc practice. Amendments require a `docs/decisions/` entry stating what changed and why, plus both authors' agreement; amendments touching registered protocols additionally follow Principle IV. When a rule here conflicts with a registered OSF protocol, the registered protocol wins.
